## 結論

標準の2自由度軌道例は、Pinocchio／RoboKots Rustの双方で、制約の実行可能性と
一階のKKT条件を満たした。等式制約を削減した座標での数値Hessianも正定値で、
厳密な局所最小解を支持する数値結果を得た。ただし、大域最適性の証明ではない。

一般の問題では `converged` は最適性の証明にならない。次の問題・制限を再現した。

## 優先度1: 境界制約のKKT診断が元の制約を使っていない

関連箇所:
`rei/optimize/dsl/spec.py::_convert_bounds_node`、
`rei/core/expr/nodes.py::HingeExpr.eval`、
`rei/optimize/kkt.py::check_kkt_conditions`。

`bounds` は違反量 `max(0, g(x))` に変換される。Hingeのヤコビアンは
`g(x)>0` のときだけ有効で、境界 `g(x)=0` ではゼロ。
現在のruntime側KKT診断はこの違反量とヤコビアンを制約として使うため、
本来必要な符号付き余裕 `g(x)` と境界での勾配が失われる。

反例: `min (x-2)^2`, `x<=1` の正解 `x=1`。

- runtime経由のKKT診断: **失敗**、停留残差1。
- 元の制約 `g=x-1`, `Jg=1` を `check_kkt_residuals()` に渡す: **成功**。

また、厳密に内側にある制約も違反量がゼロなので、活動制約数の表示が過大になる。
低レベルのKKT関数の検証と、DSLからの制約抽出の検証は分ける必要がある。

改善案: 符号付き制約値・ヤコビアンをペナルティ残差とは別に保持し、
KKT診断と制約対応ソルバーに渡す。単にHingeの境界微分を1に変えても、内側の余裕は復元できない。

## 優先度2: ペナルティ問題の収束は制約付き問題の収束ではない

Gauss–Newtonは与えられた残差を最小化する。項の `kind=eq/ineq` だけで
厳密な制約が強制されるわけではない。

`min (x-2)^2 + 100 max(0,x-1)^2` は、`x=102/101 ≈ 1.0099009901` で最小。
実行結果もこの値に `converged` したが、元の制約 `x<=1` を約0.00990違反した。
これはペナルティ問題としては正しい解で、厳密な制約付き問題の解とは異なる。

等式 `x=1` を同じ重みで残差として加えた場合も、同程度の違反が残った
（今回の実行の停止状態は `stalled`）。一方、既存のnullspace削減を明示的に
使用すると `x=1` に収束し、KKTも成功した。

改善案: 返り値・レポートでペナルティ目的の収束と制約の実行可能性を別表示する。
線形等式には既存の削減を使い、厳密な不等式が必要な問題には制約対応の求解経路を用意する。
重みを大きくするだけでは厳密な実行可能性は保証できない。

## 優先度3: 停留点であっても局所最小とは限らない

関連箇所: `rei/optimize/solvers/gauss_newton.py` の小ステップ・勾配判定。

残差 `r(x)=x²-1`、初期値0では、`J=0`, `J.T r=0` なので、
現ソルバーは `x=0`, 目的値1で `converged` を返す。
しかし目的関数 `(x²-1)²` の二階微分はこの点で-4。
ここは局所最大で、`x=±1` なら目的値0になる。

Gauss–Newton近似 `J.T J` は半正定値なので、残差の二階微分による負の曲率を検出しない。
KKTも一階条件であり、この反例の排除には使えない。

改善案: `converged` を数値停止条件と明記する。必要に応じて二階診断、初期値の変更、
複数初期値による探索を追加する。複数初期値で一致しても大域最適性の証明にはならない。

## 優先度4: 小残差による終了は小勾配を要求しない

残差 `r(x)=1e12*x+1e-11`、初期値0では、既定の `tol_r=1e-10` を満たして
即時に `converged` となる。目的値は約1e-22と小さいが、半目的関数の勾配は10。
真のゼロ残差点は `x=-1e-23`。

この例の目的値自体は十分小さいため、一律に不正な解とはいえない。
ただし「収束なら勾配も小さい」という解釈は成立しない。
改善案: 停止理由（残差／停留性／進展停止）と最終勾配を出力し、必要な条件を利用者が選べるようにする。

## 標準軌道例の結果

条件: `examples/models/planar2.urdf`、
`examples/spec/pinocchio_traj_dynamics.toml`、重力 `(0,0,-9.81)`。
201時点、制御パラメータ100、等式削減後92変数。RoboKots order=5。
Pinocchio 4.1.0と、前回と同じRoboKotsコミットをPython 3.13で使用。

| 項目 | Pinocchio | RoboKots Rust |
|---|---:|---:|
| 反復数 | 2 | 2 |
| 目的値 `r.T r` | 0.41542151283022066 | 0.4154215128302212 |
| 削減後の勾配∞ノルム（半目的関数） | 4.95e-13 | 5.19e-13 |
| 等式違反∞ノルム | 9.57e-14 | 9.57e-14 |
| 不等式違反 | 0 | 0 |
| サンプル時点の角度制限までの最小余裕 | 1.57159 | 1.57159 |
| 数値Hessianの最小固有値 | 0.01533004 | 0.01533004 |

数値Hessianは `J.T r` の中心差分から構築した。
差分幅1e-5／2e-5の双方で最小固有値は正。
非対称誤差の最大成分は約3.8e-9以下で、対称化後に固有値を評価した。
`J.T J` だけではなく、勾配全体の差分を使用している。

不等式はサンプル時点で厳密に非活動なので、このケースの局所最適性を評価するうえで
上記の境界KKTの問題は影響しない。軌道のサンプル間での制約保証は別途必要。

削減座標の解へ、標準偏差0.1／1／3の乱数を加えた3つの初期値から再実行した。
両バックエンドとも全ケースで収束・KKT成功し、同じ目的値に到達した。
ただし、この例はトルク項の重みが1e-10と小さく、動力学主体の難しい問題を代表しない。

## 再現方法と範囲

```sh
PYTHONPATH=. OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
  python developer/benchmarks/audit_forward_optimality.py \
  --output /tmp/rei-forward-optimality.json
```

スクリプトは解析的な反例とロボット例の測定値を出力する監査用であり、
全ケースを最適解に修正するものではない。出力JSONには数値Hessianと再初期化の結果を含む。
今回の対象はGauss–Newtonとその制約・診断経路。SciPy／cyipopt／liteoptの最適性保証は監査対象外。

順序として、まず元の不等式情報に基づくKKT診断を修正し、次に制約の扱いと収束表示を明確にする。
その後、対象問題に応じて二階診断・制約ソルバー・変数スケーリングを追加する。
