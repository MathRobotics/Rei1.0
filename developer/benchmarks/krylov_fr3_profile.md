# FR3 Krylov の時間内訳と単一StackExpr合算VJPの比較

2026-09-27。現在のFR3設定では、単一StackExprの合算VJP対応による
高速化は確認できなかった。修正前から3種類の動力学残差を合算している。
主な負荷はJv・Jᵀvの多数の内部反復だった。

## 条件と測定方法

- 外部 `ijrr_structured_jacobian/work/doc_ioc.py` の入力ローダーを利用し、
  順問題のみを実行。IOCと外部プロジェクトへの結果出力は実行しない。
- 現在の `work/doc_ioc.toml`、FR3v2 URDF、200区間、dt=0.01、
  30制御点、order=5。制約削減後182変数、目的残差8442成分。
- torque、torque_d1、torque_d2 が有効。
  `--random-weights --seed 0`、同一初期点。
- `gauss_newton_krylov` の既定設定を使用し、外側だけ
  `max_iters=60`、`tol_grad=1e-8`、`verbose=False` を指定。
  内部許容値1e-10、内部上限364、全アフィンGram前処理、ダンピング下限あり。
- 同一プロセスで修正前・修正後の順に各1回。変更点は、合算対象の最小候補数を
  2から、合算APIがある場合に1へ変更する条件だけ。
- モデル構築・コンパイル・制約削減は計時外。
  求解時間には前処理、履歴、進捗出力、APIの軽量タイマーを含む。
- 各求解の後、計時外で密ヤコビアンを構築して最終勾配を検証。
- Python 3.13.1、NumPy 2.5.3、macOS ARM64、BLASスレッド数1。
  RoboKotsコミット `3703e91697c737d4ce1e91ef025c9f580ef45e9b`。

現在の初期目的関数は `8.8023281442e10`、初期勾配∞ノルムは
`3.0415391682e11`。以前のFR3測定とは初期値の評価が大きく異なるため、
過去の絶対時間との直接比較はしない。ユーザーが約2倍の高速化を確認した
実行との設定一致も未確認。入力ファイルと実装のSHA-256は生データに記録。

## 時間内訳

Reiアダプターで計時した値は、ネイティブ呼出しとPython側の処理を含む。

| 処理 | 回数（前後同じ） | 修正前 | 修正後 | 修正後の総時間比 |
|---|---:|---:|---:|---:|
| Jv全体 | 20805 | 1146.286秒 | 1147.720秒 | 65.3% |
| Jᵀv全体 | 20873 | 600.131秒 | 602.006秒 | 34.2% |
| 残差評価 | 245 | 3.484秒 | 3.528秒 | 0.20% |
| 前処理Gram構築＋固有分解 | 各1 | 0.015秒 | 0.011秒 | <0.01% |
| 前処理の適用 | 20748 | 0.462秒 | 0.462秒 | 0.03% |

内訳として、ネイティブJvは62415回・997.460秒、ネイティブ合算VJPは
20873回・471.659秒（修正後）。両者で総時間の約83.6%を占める。
これらは上表のJv・Jᵀvに含まれており、上表に加算してはいけない。
状態のdynamics更新は305回・約1.08秒で、積のたびの状態再構築が主因ではない。

残差全体のJv 1回につき、トルク・1階微分・2階微分についてネイティブJvを
3回呼んでいた。一方、Jᵀvは修正前から3種類を1回の合算VJPで処理している。
したがって、今回の単一残差向けVJP修正はこの入力では経路を変えない。

## 次の改善候補

以下はこの計測時点の課題。続いて1と2を実装・検証した結果は
[Jv共有化と前処理の比較](krylov_fr3_acceleration.md)を参照。

1. **トルク微分3種類のJv計算を共有できるか調べる。**
   現在の3回のネイティブ呼出しで共通の微分計算を再利用できれば、
   最適化の計算式や許容値を変えずに改善できる可能性がある。
   3回を1回にする実装や速度改善はまだ検証していない。
2. **同じ内部精度で反復数を減らす前処理を調べる。**
   全57求解が364反復で打ち切られた。初回も相対正規残差は約2.41e-4で、
   指定の1e-10に未到達。現在のアフィン項の前処理では、この条件の
   非線形曲率を十分に扱えていない可能性がある。
3. **Python側の準備情報の再利用は、その後に評価する。**
   ネイティブ微分計算が約84%なので、Python処理だけの改善には限界がある。
   残差評価や前処理構築の短縮を最優先にする根拠はない。

内部精度を緩める変更は今回試していない。収束経路を保つ要望に合わせ、
まず同じ積と同じ線形問題を効率よく計算する方向を優先する。

## 再実行

[スクリプト](krylov_fr3_profile.py)と[生データ](krylov_fr3_profile_results.json)。
外部プロジェクトの入力とRoboKotsが利用できるPython環境が必要。

```bash
PYTHONPATH="$PWD" OPENBLAS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 \
  /path/to/ijrr_structured_jacobian/.venv/bin/python \
  developer/benchmarks/krylov_fr3_profile.py \
  --doc-script /path/to/ijrr_structured_jacobian/work/doc_ioc.py \
  --output /tmp/fr3-profile.json
```

測定用の切り替えはプロセス内でのみ行い、終了・例外時に元へ戻す。
最初の進捗なしの長時間実行は途中中断し、計測器修正後に再実行した。
中断実行と、進捗コールバックの渡し方を修正する前の失敗実行は結果に含めていない。
